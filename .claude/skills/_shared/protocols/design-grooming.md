# Design Grooming Protocol

> **Purpose:** Defines how Claude Design integrates into the sdlc-automation-agent grooming cycle — signal detection, artifact conventions, SE consumption rules, and lifecycle guards.

Claude Design is Anthropic's visual creation tool (powered by Claude Opus 4.7) that generates interactive prototypes, mockups, and slide decks. Its **handoff bundle** (design spec + CSS intent + component tokens) is the bridge between client-approved designs and Claude Code implementation.

---  

## Signal Detection (opt-in)

Invoke Claude Design when **any** of the following signals are present: 

**Story-level signals:**
- Story title or description contains UI/UX keywords: `UI`, `UX`, `frontend`, `interface`, `wireframe`, `mockup`, `prototype`, `screen`, `flow`, `dashboard`, `form`, `layout`, `page`, `component`, `design`
- Story is tagged `[DESIGN]` or `[DESIGN-PENDING]`

**Feedback-level signals:**
- Client feedback mentions visual uncertainty: "doesn't look right", "redesign", "change the layout", "new screen", "I want to see", "show me", "can we visualise", "what will it look like"
- Sprint Review feedback mentions new user flows, navigation changes, or visual overhauls 

**Sprint/project-level signals:**
- Sprint Goal is primarily UI/UX focused (majority of stories have UI signals)
- Greenfield project with web or mobile UI surface (detected at Inception)
- `.sdlc-automation-agent.yaml` → `project.framework` is a web/mobile framework (nextjs, sveltekit, nuxt, remix, react-native, flutter)

**Skip Design when:**
- Story is backend-only (API endpoints, DB migrations, caching, infrastructure)
- Story is tagged `[ENABLER]`, `[INFRA]`, `[DATA-MIGRATION]`, or `[SECURITY]`
- No UI surface in the project

## Context Ingestion Mechanics

Claude Design understands project context through three concrete inputs — not magic. Whoever drives the prompt must provide them explicitly. 

### 1. Codebase connection (one-time, at Inception)

Claude Design connects to the project's GitHub repo once and extracts the design system automatically. It parses source files via Tree-sitter AST to infer:  
- Brand colors and typography from CSS/Tailwind/theme files 
- Component library (React/Vue/Svelte component definitions, exports, props)
- Spacing and layout tokens 
- Design system metadata 

This is persistent — every subsequent prototype inherits the extracted system without re-feeding. Set up at Inception Step 2.5a. Recorded as `connected_repo: {owner}/{name}` in `inception-preview.md`.

### 2. Web capture (per invocation)

Claude Design's web capture tool reads the **live DOM** from a URL — not a screenshot. It captures: 
- Actual rendered styles across 4 breakpoints
- Hover / focus-visible / active / pressed interactive states
- Modal and popover layers  
- Animation and transition specs

**Canonical input:** the preview URL generated by Sprint Review Step 1 (`modes/preview.md`). For Sprint Review Step 5.5, paste the Step 1 URL into Claude Design before typing the redesign prompt.

### 3. Document upload (per invocation)

For feature-specific context, paste or upload:
- The specific story description(s) from the tracker
- The relevant feedback excerpt from `.sdlc-automation-agent/.orchestrator/sprint-feedback.md`
- The relevant BRD or feature brief section, if applicable

### Prompt template (Sprint Review Step 5.5) 

``` 
Context to paste into Claude Design:
  1. Web capture URL: {preview_url from Step 1}
  2. Feedback excerpt: {relevant entry from sprint-feedback.md}
  3. Story context: {story description(s) from tracker}
  4. Existing prototypes (if any): {links from previous sprint-{N}-preview.md}

Instruction: "Redesign [affected surface] based on the feedback above. 
Keep the existing design system (already connected). Generate 2-3 variants
for side-by-side comparison."
```

For single-story invocation at Sprint Planning Step 2 (resolving `[DESIGN-PENDING]`):
``` 
Context:
  1. Web capture URL: {preview_url or "N/A — new feature"}
  2. Story: {full story description + ACs}
  3. Sprint preview (if relevant): .sdlc-automation-agent/design/sprint-{N}-preview.md

Instruction: "Generate a prototype for this story. Use existing components  
where possible. Output: handoff bundle."  
```

## Artifact Conventions

### Directory structure 
```
.sdlc-automation-agent/ 
  design/ 
    inception-preview.md        ← Vision prototype reference (Inception only)
    sprint-{N}-preview.md       ← Sprint-level prototype overview (Sprint Review)
    {story-id}-design.md        ← Per-story handoff bundle (Sprint Planning)
```

### inception-preview.md — Vision prototype reference
```markdown
# Inception Design Preview

> Sprint 0 — Product Vision Prototype

## Prototype URL
{Claude Design shareable URL}

## Key Screens
- {Screen 1 name}: {brief description}
- {Screen 2 name}: {brief description}

## Stakeholder Approval
- [ ] Approved at Inception Gate  
- Approved by: {name}  
- Date: {date}

## Design System Seed
{Brand tokens, color palette, typography extracted from prototype}
```

### sprint-{N}-preview.md — Sprint-level prototype overview
```markdown
# Sprint {N} Design Preview

> Generated at Sprint {N} Review — input for Sprint {N+1} grooming

## Proposed Next-Sprint Prototypes 

### {Feature/Story Title}
- **Claude Design URL:** {shareable URL}  
- **Key screens:** {list}
- **Client feedback:** {recorded async feedback from client review}
- **Stories to create/update:** {story IDs if known} 

## Design System State 
{Any updates to brand tokens or component library from this sprint}
```

### {story-id}-design.md — Per-story handoff bundle

Anthropic has not published a JSON schema for Claude Design's handoff bundle as of April 2026. To make SE consumption deterministic, sdlc-automation-agent pins the local handoff file to this format. The person capturing the bundle fills each section from the Claude Design export (copy-paste from the handoff panel) — anything the export lacks gets filled manually before the story enters `queued`.

```markdown
# Design Handoff: {story-id} 

> Generated at Sprint Planning — SE must parse this before writing UI code.

## Prototype
prototype_url: {claude-design-shareable-url}
prototype_version: {version-id from Claude Design} 
approved_at: {ISO8601 timestamp}
approved_by: {client-name or stakeholder-name}

## Component Inventory

| Component | Variants | Props (type hints) | Source | 
|-----------|----------|--------------------|--------|
| Card | default, elevated | variant: "default"\|"elevated"; padding: number | existing:components/Card.tsx |
| StatTile | default | label: string; value: number; delta: number | new |

`Source` is either `new` (SE creates it) or `existing:{path}` (SE reuses — never regenerate).

## Design Tokens (delta from project defaults)

Only tokens that differ from `frontend/app/styles/tokens/`. SE merges these — does not replace the file. 

```yaml
colors:
  accent-500: "#7C3AED" 
  accent-contrast: "#FFFFFF" 
typography:
  heading-display: "2.5rem / 1.1 / 700"
spacing:
  card-inner: "20px"
```

## Layout Intent
- Grid: 12-column, 24px gutter, 1280px max width
- Responsive: mobile stacks, tablet 2-col, desktop 3-col
- Breakpoints: project defaults (do not override)  

## Interaction Spec
- hover: card elevation +1
- focus-visible: 2px accent-500 ring, 2px offset
- active: scale 0.98 
- reduced-motion: disable all scale transforms, keep colour transitions

## Implementation Notes
{Free text — a11y constraints, edge cases surfaced during prototype iteration, any 
"this is approved but we know it has to change if X" caveats.} 
```

## Story Field Extension

Stories with a Design artifact carry a `design_ref` field in their tracker metadata:

```
design_ref: .sdlc-automation-agent/design/{story-id}-design.md
```

Stories where Design is required but the bundle has not yet been generated carry:
```
tags: [DESIGN-PENDING]
```

`[DESIGN-PENDING]` is resolved during Sprint Planning Step 2 — never enters `queued` state without resolution.

## Client Collaboration & Permissions

Claude Design exposes three permission levels on a shared prototype: **Private**, **View-only (with comments)**, and **Edit**.

**Default for clients:** View-only with comments enabled. Clients can click any component on the prototype canvas and leave an inline comment. Claude Design sees the comments and the PM can iterate against them in the same project.

**Open assumption:** Anthropic has not documented whether viewers need a Claude account to comment. Treat as "comment requires an account" until confirmed — if the client lacks one, fall back to screenshot-plus-written-feedback via email or the existing `sprint-feedback.md` path.

**Side-by-side alternatives.** When generating 2-3 variants for a single decision point, produce them all in the same Claude Design project and share one URL — clients pick in one round instead of N separate reviews. 

### Client Sharing Flow

1. PM generates prototype(s) in Claude Design (repo connection from Inception seeds the design system automatically)
2. PM sets permission to **view-only + comments** and shares the URL with the client
3. Client reviews asynchronously — clicks components, leaves inline comments
4. PM polls Claude Design project for comments during Refinement Mode (no webhook support as of April 2026)
5. PM copies each material comment into `.sdlc-automation-agent/.orchestrator/sprint-feedback.md` under a `## Design Comments` subsection so the standard feedback loop picks it up
6. Once the client approves a specific variant, PM captures the handoff bundle into `.sdlc-automation-agent/design/{story-id}-design.md` using the format above

## SE Consumption Guardrails

When a story has `design_ref` set, the SE **must**:

- Parse `.sdlc-automation-agent/design/{story-id}-design.md` before writing any UI code — this is mandatory input, not a suggestion
- Treat the Component Inventory as authoritative: reuse `Source: existing:{path}` components rather than regenerating them 
- Merge Design Tokens into `frontend/app/styles/tokens/` as a delta — **never replace the entire tokens file**; preserve tokens the handoff does not mention 
- Use Layout Intent and Interaction Spec as the basis for Tailwind classes / CSS — do not derive layouts from WebSearch or intuition when a handoff exists
- Record deviations in the SE receipt under `design_impl_notes` (see `receipt-protocol.md`)
- Include `design_ref` in the receipt's `artifacts` array

The SE **must not**:

- Override tokens defined in the handoff with arbitrary Tailwind values or hardcoded CSS
- Add components that are not in the Component Inventory unless the addition is recorded as `design_impl_notes: component added because <reason>`
- Skip frontend Phase 5 (Design & Polish) entirely — Phase 5 has a dedicated conditional that replaces WebSearch research with handoff data, it does not skip polish work
- Change `prototype_url` or `approved_by` in the handoff file — those are client-approved and immutable; any change must re-route through Refinement Mode

### SE Receipt Requirements

When `design_ref` is set, the SE receipt (`{story-id}-se.json`) must include:
- `design_ref` — same path as the story's tracker field
- `design_verified` — boolean, true iff the rendered preview visually matches the prototype within team tolerance (manual verification in this iteration)
- `design_impl_notes` — required if any deviation from the handoff was made; empty string otherwise 

See `receipt-protocol.md` for field semantics.

## Lifecycle Guards

| Ceremony | Guard | 
|----------|-------|
| Inception | Design step runs only if project has a web/mobile UI surface |
| Sprint Review | Step 5.5 runs only if UI signals in feedback or proposed next-sprint stories | 
| Refinement | Design classification runs only when feedback has visual/UX signals |
| Sprint Planning | `[DESIGN-PENDING]` must be resolved before story enters `queued`; skip for backend stories |
